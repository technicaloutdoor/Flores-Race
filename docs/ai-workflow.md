# AI-assisted workflow and model tiering

This project is developed with AI coding agents. The owner's instruction was explicit: use the most
capable reasoning model where judgement matters, and cheaper, faster models wherever heavy reasoning
is not needed. This document records how that policy is applied so the team can keep following it.

## Tiers

| Tier | Used for | Why |
|---|---|---|
| **Frontier reasoning model** (the most capable tier available) | System architecture and data model; the route concept (where to go, why, cultural and safety judgement); reviewing and synthesising verification results; anything that decides what the team will spend field days on | Mistakes here are expensive to discover (a bad anchor list wastes a scouting trip) and hard to detect mechanically |
| **Mid-tier coding model** | Writing the pipeline and web application code from a precise spec; refactors; tests; research agents that gather and cross-check facts with web search | Well-specified engineering with tight feedback loops (compilers, tests, screenshots) catches errors cheaply |
| **Small fast model** | Boilerplate and configuration; converting a written contract into JSON Schema and TypeScript types; documentation drafts from an outline; data formatting; screenshot capture and file inventories | Mechanical, deterministic, easy to validate |

## Verification pattern for facts

Geographic facts (coordinates, elevations, names, eruption history) are generated by one agent and
**independently challenged** by two or three others with a different lens (coordinate plausibility
against the DEM and coastline, source agreement via web search, naming and spelling). Only facts that
survive are marked `verified`; the rest are `approximate` or `unverified` and are visible as such in
the app. The frontier model reads the disagreement reports and decides.

## Verification pattern for code

Generated code is judged by: the TypeScript compiler and the Python validator; a headless browser
run that loads each mode and screenshots it; and an adversarial review agent asked to break it.
Findings go back to the coding tier; the architecture only changes at the frontier tier.

## What never goes into the repository

Model identifiers, session links or vendor names in code comments, commit messages or generated data.
The repository documents *tiers* and *roles*, not products.
