# ADR-0005: Model tiering for AI-assisted work

**Status:** Accepted

**Context**
This project is developed with AI assistance. The team wants to maximize value (capable reasoning for decisions, fast iteration for engineering) while managing costs and keeping the project explainable.

**Decision**
Adopt a three-tier model policy: Frontier reasoning for architecture, route design, and verification (expensive, high judgment). Mid-tier coding for pipeline, web app, and research agents (efficient, well-specified). Small-fast models for boilerplate, schema generation, and documentation (cheap, mechanical).

Geographic facts are generated by one agent and independently challenged by two others; only facts surviving all checks are marked `verified`. Code is judged by the compiler, schema validator, browser tests, and an adversarial review. No model names, session links, or vendor names appear in code or data.

**Consequences**
- Decisions that steer field work use the strongest reasoning available.
- Engineering is fast and tight (spec + tests catch errors).
- Transparent about the role of AI without committing to a specific vendor.
- Team can rotate agents without breaking the workflow.

**Alternatives considered**
1. *All frontier tier:* Cost-prohibitive; wastes strong reasoning on boilerplate.
2. *All small-fast:* Poor quality for decisions; misses bugs in engineering.
3. *No tiering, single model:* Impossible to optimize for both judgment and cost.
